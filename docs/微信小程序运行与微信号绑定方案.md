# 微信小程序运行 ERPNext 版本与微信号绑定方案

ERPNext 不能直接运行在微信小程序里面。正确架构是：

```text
微信小程序前端
    |
    | HTTPS API
    v
ERPNext / Frappe 后端
    |
    v
shop_assistant 自定义 App
```

也就是说，小程序只是移动端界面，所有数据、权限、角色、订单、商品库、送货任务都放在 ERPNext 服务器里。

## 1. 服务器要求

ERPNext 服务器必须有 HTTPS 域名，例如：

```text
https://erp.yourdomain.com
```

原因：

- 微信小程序正式版只能请求已备案/已配置的 HTTPS 域名。
- 拍照、上传文件、扫码、登录都需要稳定的 HTTPS API。
- Frappe 登录态需要通过安全域名维持。

## 2. 微信小程序后台配置

进入微信公众平台的小程序后台：

```text
开发管理 -> 开发设置 -> 服务器域名
```

把 ERPNext 域名加入：

```text
request 合法域名：https://erp.yourdomain.com
uploadFile 合法域名：https://erp.yourdomain.com
downloadFile 合法域名：https://erp.yourdomain.com
```

## 3. ERPNext 站点配置微信 AppID 和 Secret

在服务器的站点配置里加入：

```bash
cd ~/frappe-bench
bench --site erp.yourdomain.com set-config wechat_mini_appid "你的小程序AppID"
bench --site erp.yourdomain.com set-config wechat_mini_secret "你的小程序AppSecret"
bench --site erp.yourdomain.com clear-cache
```

AppSecret 不要写进前端代码，也不要提交到 GitHub。

## 4. 安装本项目的微信绑定表和登录 API

当前自定义 App 已经新增：

```text
Shop Wechat Binding
shop_assistant.api.wechat.wechat_login
```

部署或更新后执行：

```bash
cd ~/frappe-bench
bench --site erp.yourdomain.com migrate
bench build
sudo supervisorctl restart all
```

## 5. 小程序登录流程

小程序端调用 `wx.login`，拿到临时 `code`：

```js
wx.login({
  success(res) {
    wx.request({
      url: 'https://erp.yourdomain.com/api/method/shop_assistant.api.wechat.wechat_login',
      method: 'POST',
      data: {
        code: res.code
      },
      success(loginRes) {
        console.log(loginRes.data.message)
      }
    })
  }
})
```

后端会用 `code` 请求微信的 `code2Session` 接口，换取 `openid`。

## 6. 第一次登录如何绑定角色

第一次微信登录时，如果系统还没有绑定这个 `openid`，后端会自动创建一条：

```text
Shop Wechat Binding
```

状态是未启用。

老板或系统管理员进入 ERPNext：

```text
Awesomebar 搜索 -> Shop Wechat Binding
```

找到这条记录，然后填写：

- ERPNext User：绑定到哪个 ERPNext 用户
- Enabled：勾选
- Shop Role Profile：选择这个用户在店铺系统里的角色范围

ERPNext 用户本身也要分配对应角色，例如：

- Shop Boss
- Shop Sales
- Shop Warehouse
- Shop Delivery
- Shop Supplier
- Shop Accountant

## 7. 第二次登录

用户再次打开小程序：

1. 小程序调用 `wx.login`
2. 后端换取 `openid`
3. 根据 `Shop Wechat Binding` 找到 ERPNext User
4. 自动登录 ERPNext
5. 返回用户角色
6. 小程序根据角色展示对应页面

例如：

```json
{
  "bound": true,
  "user": "sales@example.com",
  "roles": ["Shop Sales"]
}
```

小程序可以根据 `roles` 控制首页入口：

- `Shop Boss`：销售统计、全部订单、权限配置
- `Shop Sales`：下单、订单列表、商品库、供应商生产单
- `Shop Warehouse`：库存、货位、到货、验货
- `Shop Delivery`：今日送货、返单、签字单上传
- `Shop Supplier`：生产单、进度上报
- `Shop Accountant`：付款状态、订单金额统计

## 8. 小程序如何访问 ERPNext 数据

小程序请求 Frappe API：

```text
GET /api/resource/Shop Order
GET /api/resource/Shop Product
POST /api/resource/Shop Delivery Task
POST /api/method/shop_assistant.api.product.get_product_by_barcode
POST /api/method/upload_file
```

文件上传可以使用 Frappe 自带接口：

```text
POST /api/method/upload_file
```

上传商品照片、正唛、侧唛、条码、签字单时，统一走这个接口。

## 9. 权限在哪里控制

权限分两层：

### ERPNext / Frappe 原生权限

在 DocType 权限里控制谁能读、写、删除、导出。

当前自定义 App 已经给这些角色配置了基础权限：

- Shop Boss
- Shop Sales
- Shop Warehouse
- Shop Delivery
- Shop Supplier
- Shop Accountant

### Shop Role Profile

这个是本项目自己的角色配置表，用来进一步控制小程序里显示哪些页面、哪些按钮、哪些操作。

例如：

```json
{
  "pages": ["orders", "products", "delivery"],
  "actions": ["create_order", "upload_photo", "scan_barcode"]
}
```

小程序登录后读取这个配置，再决定显示哪些入口。

## 10. 和当前 uni-app 前端的关系

如果继续使用 `frontend/` 里的 uni-app，可以把它改成小程序端：

```bash
cd frontend
npm install
npm run build:mp-weixin
```

但是当前 `frontend/` 主要连的是旧 Node 后端。要接 ERPNext，需要把请求地址改成：

```text
https://erp.yourdomain.com/api
```

并把登录流程改成微信登录 + Frappe Cookie/API 调用。

更推荐的下一步是单独做一个 `frontend/wechat` 或改造现有 uni-app，使它只面向 ERPNext API。

## 11. 官方文档

- 微信小程序登录：`wx.login` 和 `code2Session`
- Frappe REST API：`/api/resource` 和 `/api/method`
- Frappe 文件上传：`/api/method/upload_file`
